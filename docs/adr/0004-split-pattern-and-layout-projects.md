# 型紙プロジェクトと配置プロジェクトの分離

型紙の登録（写真・校正・トレース）と、生地への配置・判定を別ワークフローに分け、それぞれ **型紙プロジェクト** と **配置プロジェクト** として独立させる。

従来は1つのプロジェクトに写真・パーツ・生地・配置がすべて入っていたが、登録と配置は目的・寿命・変更頻度が異なる。型紙は登録後ほとんど変更せず、配置プロジェクトは使い捨てに近い。ホーム画面も2つのリストに分ける。

配置プロジェクトは型紙プロジェクトを単位で選び（同一プロジェクトの複数選択可）、選んだ型紙の全パーツを配置対象とする。パーツはライブ参照とし、型紙プロジェクトまたはパーツの削除時は関連する配置から自動除去する（参照整合より実装の単純さと型紙優先を選んだ）。既存データは型紙プロジェクトへ移行し、生地・配置情報は破棄する。

**Considered Options:** 1プロジェクト内でUIフェーズのみ分離（データは一体）、配置時にパーツを個別選択、配置時にパーツ形状をスナップショット。

**Consequences:** DB スキーマとルーティングが2系統になる。配置プロジェクト削除時に型紙データには影響しない。
